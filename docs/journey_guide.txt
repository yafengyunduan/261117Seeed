四个初始姿态统一设置（2026-11-16）
文件：config/261105_my_elevator.yaml，开头的initial_poses。
- grasp_ready：夹取预备位。x/y/z为base坐标系end_link位置，单位米；roll/pitch/yaw为弧度；duration为秒。
  当前预备位为 XYZ=[0.3,0,0.3]m、RPY=[0,0.7,0]rad，参考 2.5 秒。抓取结束返回预备位也使用此项。
  启动时，joint4_stage_duration_s 大于 0 会先固定 J4，让其他五轴按 duration 到位并停稳，再单独转动 J4。当前第二段参考 1.5 秒。
- call_view_deg 设置外呼上下键初始视角，填六轴绝对角度（度）。
- floor_view_deg 设置轿内楼层按键初始视角，填六轴绝对角度（度）。
- display_view_deg 设置 LCD 楼层显示识别初始视角，填六轴绝对角度（度）。
外呼和楼层按键可独立调整。外呼结束先恢复floor_view_deg；人工进轿厢站稳后按C，不重复下发姿态。
三个视角均只填前六轴，第七轴继续取gripper.closed_angle_deg；运动参考时间继续取startup_view.duration_s。
startup_view 设置共用的抬头时间与到位检查。搜索等待和重试角度也在 261105_my_elevator.yaml 中设置。
261113总流程读取全部四项；261110串联入口读取grasp_ready和floor_view_deg。修改后重启程序生效。
夹取预备位只在运行时映射到原main.py使用的ready_pose接口，不修改原config/default.yaml或原main.py。
grasp_place.xyz_m仍是独立的放置点；未指定--place-rpy-deg时，放置roll/pitch仍沿用夹取预备位。

按键与操作顺序
1. GRASP：启动先按原main.py流程进入initial_poses.grasp_ready指定的夹取预备位，再等待G/N。
   G只请求新的抓取观测，不重复移动到预备位；成功后搬运到放置点、松爪。
   放置点统一在config/261105_my_elevator.yaml的grasp_place.xyz_m中设置，当前[0.2,0.2,0.2]m。
   这是base坐标系中的end_link XYZ，不叠加电梯或视觉目标偏移；261110与261113共用。
   --place-xyz-m X Y Z可仅在本次运行覆盖配置；原放置朝向、动作时间和松爪顺序不变。
   N跳过整个抓放环节。结束后共用机器人会话切换到电梯夹爪模式、闭合并进入抬头姿态。
2. WAIT_CALL：抓放完成（或按 N 跳过）并抬头后，等待人工确认。到外呼面板前站稳后按 C 开始识别和计时。
   第一次C才进入CALL，清除旧观测、确认静止并开始识别两键外呼面板；不重复抬头。
   当前稳定后按U选择上行、D选择下行。
   WAIT_CALL或CALL按N可跳过外呼，恢复抬头后进入BOARD；仍需人工进轿厢并站稳后按C继续。
   稳定外呼结果暂存完整RGB-D和拍摄位姿；有效期沿用261105配置的elevator.stable_snapshot_age_s，当前2秒。
   U/D可复用短暂漏检前的稳定结果，不必额外等输入后的检测。执行前核对上下两个局部图像、深度和位姿。
   场景改变、过期、阶段/运动批次切换或出现多键歧义时，缓存不再用于执行。
   上下行按图像上下位置判定，要求相机正立和常规竖排两键布局。
   对当前圆环中心取新的同帧RGB-D与拍摄位姿，执行所选接近或实体触压流程，随后恢复floor_view_deg。
3. BOARD：等待操作员确认。人工完成开门检查、搬位/进轿厢及机身站稳后，按C继续。
   程序没有机械狗导航、避障、门开检测、自动进轿厢或底盘控制接口。
   这一确认不能省略为“按完外呼后立即开始寻找轿内按键”。
   外呼动作后已恢复楼层按键初始视角，按C仅清除旧观测并重新采集静止画面，不重复下发相同姿态。
4. FLOOR：识别轿内数字按键面板。在窗口或终端直接输入楼层，无需回车；默认停顿0.4秒自动提交。
   例如按3后停顿即选择3；连续输入12、-1或-12后停顿则提交完整楼层，退格可在提交前修改。
   --floor-input-delay-s可调整停顿时间，范围0到2秒；默认0.4秒用于区分单数字与两位数。
   楼层阶段终端使用逐键读取，等待 LCD 启动及补输到站目标时也可直接按键。
   261105配置的elevator.floor_cache_until_update=true：已确认过的楼层在本阶段持续缓存，不再按2秒或处理帧数过期。
   每个楼层只保留最新一份完整稳定RGB-D、圆环及拍摄位姿；临时漏检、低置信度或圆环变黄不会清除。
   输入曾确认的楼层即可选择缓存，无需当前圆环为绿色，也不要求输入后重新执行OCR。
   后续唯一稳定识别会更新相应楼层；同一位置确认成另一楼层时替换旧映射。暂时不稳定的OCR候选不替换确认值。
   执行前核对局部像素、深度、相机位姿及新的稳定数字冲突；当前场景匹配后才使用这份完整观测。
   运动/阶段切换后清空缓存；FLOOR按R可手动清空并在当前姿态重新识别，不额外移动机械臂。
   窗口底部memory=[...]列出已确认缓存；source=LATCHED_FLOOR_CACHE表示本次使用持续缓存。
   将floor_cache_until_update改为false可恢复原stable_snapshot_age_s定时缓存；外呼和旧入口缓存行为不变。
   通过标签记忆绑定的当前圆环也可刷新稳定图像缓存，不必每次重跑同一数字OCR。
   取得当前唯一可靠圆环和有效深度后执行动作；不存在或不可靠的楼层不会由布局推算后直接运动。
   按 N 可跳过楼层按键，包括已排队但还未开始的请求。已选择或正在输入的有效楼层会保留为到站目标。
   对容易漏读的1新增独立位置证据：至少3个已经多次识别的数字作布局锚点，
   当前实测圆环内有单竖笔画像素，且所有可行排序均允许这里是1，连续3次一致后标为“1 P”。
   P不是OCR读取或置信度；输入1可沿既有深度/变换/按键偏移执行。文字字段不会被改写为1。
   不从布局凭空生成圆环，不把0楼缺失作为默认假设；负号、数字冲突、多个1候选和无笔画均不补齐。
5. WAIT_DISPLAY → DISPLAY
   楼层按键完成或按 N 跳过后，机械臂进入 initial_poses.display_view_deg，等待 C 开始识别。
   按 C 后核对停稳，开始 LCD 识别和搜索计时。已有楼层目标时同时开始到站计时。
   若跳过时还没有到站目标，可在 DISPLAY 直接输入楼层，停顿 0.4 秒提交。此输入仅用于对照 LCD，提交后开始到站计时。
   独立 OCR 连续稳定且 current_floor 等于到站目标后回零并退出。
   等待 C 或识别期间按 N，实机调用原 SDK 回零并退出，预览直接退出。
   observed_floor候选、last_confirmed_floor历史值、屏幕外按键数字都不能作为到站条件。
   这是用户指定的“楼层显示匹配”结束条件，不能证明轿厢已经停车或开门；不要据此自动让机械狗出轿厢。

搜索与重试
- 每阶段有一个初始搜索窗口，最多两次姿态重试。各窗口时长取 config/261105_my_elevator.yaml 的 search_timeout_s.call、floor、display。
- CALL、FLOOR 和 DISPLAY 共用 261105_my_elevator.yaml 中的 search_retry_delta_deg。每次从实测角度让 J2 减 15°、J3 减 25°，其他四轴保持反馈角度。
- 所有抬头目标在发送前核对当前机械臂模型的六轴 URDF 关节限位。预设角度越界会报告轴号、目标角和允许范围。
- 两轴按各自剩余范围缩短步长。有一轴到限位时，另一轴有余量仍可继续。两轴均无剩余行程且当前视角未检出时，结束搜索并回零。
- 首轮窗口从按 C 并确认停稳后起算。重试窗口从本次抬头结束并确认停稳后起算。WAIT_CALL、BOARD、WAIT_DISPLAY 等待人工确认期间不计时。
- 已得到稳定面板后可以等待 U/D 或等待用户输入楼层，等待期间不触发抬头。
- LCD已稳定读到非目标楼层时持续等到站，不把正常乘梯时间当作搜索失败。
- 到站等待另有arrival_timeout_s，当前默认300秒；到达该总等待上限则结束并回零。
- 换姿态、机械狗搬位和阶段切换后，旧RGB-D目标及识别稳定性失效，重新积累证据。
- 重试用尽仍不能取得可靠观测时，结束任务并尝试 SDK 回零后退出。

停止与回零
- N/n 跳过 WAIT_CALL/CALL、FLOOR 或 WAIT_DISPLAY/DISPLAY 的当前阶段。BOARD 按 C 确认进轿厢并站稳。
  图像窗口直接按 N。终端在楼层输入、等待 LCD 启动或补输到站目标时直接按 n，其他阶段输入 n 再回车。
  正在执行按钮动作时，通过原取消回调先停止；末端已偏离本次动作起点时回撤到原定前置点，再恢复观察姿态。
  动作尚未开始时直接切换，不为回撤而向按钮前置点移动。停止、通信或回撤执行故障时终止任务，不追加新姿态。
  若回撤本身在轨迹发送前被IK规划拒绝，则按下述IK恢复规则调用safe_home。
  跳过时清除旧识别缓存、未执行的按键请求和输入计时，下一阶段重新采集证据。
- FLOOR 阶段按 R/r 清空已确认楼层缓存、待执行选择及输入，在当前姿态重新识别并开始新的搜索窗口。
  SDK同步规划期间取消回调可能延迟；保持原SPACE/ESC停止和Q回零退出方式。
- 正常完成、搜索重试耗尽、按钮三帧确认超时或轨迹规划/到位失败：任务结束。通信和控制可用时调用SDK safe_home，核对回零后自动退出。
  回零使用关节角零位目标，不会重新规划失败的笛卡尔目标；不修改编码器零点。任务失败不会计为按键成功。
  反馈不全、控制器未运行或发送线程不能停止时，不能保证回零或维持姿态。
  规划期间排队的停止/取消按键优先处理；SPACE/ESC不触发上述自动回零恢复。
- Q/q：结束任务，停止当前指令后使用SDK safe_home回零并自动退出。窗口按Q；楼层阶段终端按q即可，其他阶段终端输入q再回车。
- SPACE、ESC、关闭窗口或终端stop：停止当前指令并退出，不追加回零动作。
  急停后的自动回零会引入新的运动，因此与正常结束分开处理。
  SDK规划、通信和发送停止存在处理延迟，键盘取消不等同于硬件实时急停。
- 控制故障、失去通信或发送线程无法停止时，回零不能保证完成，应以实际退出反馈为准。
- 任务结束后自动关闭相机、推理进程和本地电机控制会话，不发送失能命令；退出后不再持续发保持指令，力矩能否维持取决于电机端通信保护。软件停止不代替硬件急停。

机械狗搭载时的准确性前提
- 机械臂base坐标原点随机身移动。运动到按钮期间，机身应保持静止并处于稳定支撑状态。
- 现有末端位姿来自机械臂六轴FK，不包含机械狗在世界中的平移、俯仰和晃动。
  仅比较关节FK不能证明机身未动，也不能将旧三维按钮坐标跨行走阶段沿用。
- 启用备份中的水平前置点时，roll/pitch=0 以机械臂 base 为参考。底座水平时，这个姿态才对应重力水平。
- 三帧复核模式用 RGB-D 面板法向计算前置方向。水平前置位 IK 失败时走原回零流程。
- 完成前置接近或接触撤回后再恢复观察姿态；URDF关节限位内的姿态不等于对机身、墙壁或轿门无碰撞。
- call_target_offset_base_m当前为null：按用户确认动态继承数字按键的target_offset_base_m。
  若将来需独立校准外呼，可改成三元素向量；[0,0,0]表示明确关闭外呼目标修正。
- 数字按键仍沿用现有config/261105_my_elevator.yaml中的目标补偿。
  这组经验值、工具偏移和手眼标定需在新安装、姿态或场景下复核。
- 外呼两键此前验证的是视觉定位，新接入的外呼三维接近还需实测，可选用approach单独核验。
- 数字按键OCR沿用用户既有配置，当前min_confidence=0.70；LCD独立识别阈值为0.80。
  两者是不同任务的置信度阈值，不是实测准确率，程序不会用文件名或预期楼层填补识别结果。
- 完整自主乘梯还缺门状态/进出导航/底盘站稳信号/真实按钮触发确认，本入口保留人工阶段确认。
